# 観測データと海洋モデル：時刻・単位・鉛直座標

位置推定を始める前に、タグのデータと環境データが同じ物理量を比べているかを確認します。同じ名前の列があっても、時刻の基準、圧力と水深、海面と海底の基準面が同じとは限りません。

## 1. 入力を整理する

| 入力 | 科学的な役割 | 確認する情報 |
|---|---|---|
| タグの温度・圧力・深度 | 魚が経験した環境 | 単位、校正、記録間隔、時刻ずれ、欠測、センサー位置 |
| 放流・再捕・死亡等のイベント | 既知位置に関する情報 | イベント種別、緯度経度、位置と時刻の不確かさ |
| 音響検出 | 受信機付近にいた情報 | タグID、受信機ID、受信時刻、誤検出処理 |
| 受信機設置記録 | 未検出を解釈する条件 | 設置・回収、停止、移設、受信範囲の試験 |
| 海洋モデル | 温度、海面高度、鉛直座標 | 変数の定義、時刻の意味、時間境界、海陸マスク |
| 海底地形 | 潜れる深さの制約 | 鉛直基準面、格子間隔、元の測量情報、符号 |
| 潮汐調和定数 | 潮位変動の予測 | 振幅単位、位相規約、時刻基準、分潮、版 |

上の表は、データを用意するときの確認項目です。ノートブックが受け取る列名やイベント名は、pangeo-fish の版（`361e9b7`）の入力形式に合わせます。`docs/format.md` では、`dst.csv` は `time`・`temperature`・`pressure` の列、`tagging_events.csv` は `event_name`・`time`・`latitude`・`longitude` の列、`acoustic.csv` は `deployment_id` と `time` を必須とします。`stations.csv` は受信機の設置・回収の時刻と位置（`deploy_*`、`recover_*`）を持ちます。位置の手がかりに使われるのは放流（`release`）と死亡（`fish_death`）の行で、再捕（`recapture`）の行は使われません。`fish_death` の緯度経度が `NA` なら、終端位置の制約は作られません。

## 2. UTCとモデルの時間ビン

タグの10分値、潮汐の予測値（`healpix` 方式は1時間平均、`pedersen` 方式は10分サンプルのまま比較）、水温の日平均値は、それぞれ時間の刻みが異なります。タグの値をどの日・どのモデル時間区間に割り当てるかで、比較される環境が変わります。

`compute_diff`は、参照モデルの時間区間（各時刻が表す時間の始まりと終わり）に従ってタグの値をグループ化します。日付のラベルだけを見て、午前0時の瞬間の値とは解釈しません。日本時間で記録した観測をUTCに直す場合は、元のタイムゾーンと変換の履歴を残してください。潮汐では位相の合わせ方にも影響します。

同じ日の平均温度でも、魚は移動し、深さを変えています。日ごとの重みは、「その一日を一つの位置で代表させる」近似を含みます。この近似が妥当かどうかは、記録間隔、魚の移動距離、環境の変化から判断します。

**図を追加する場合の実データ例：** タグの生時系列、モデルの時間ビン、ビンごとの有効サンプル数を上下に並べます。欠測した日と、観測はあるがどの候補位置とも整合しない日を別に表示します。

## 3. `pressure`という列名を水深の単位と取り違えない

デモの`pressure`列は、正の下向きの水深（m）としてそのまま計算に使われます。新しいタグの圧力がdbarなら、列名を合わせる前に、どう換算するかを決めてください。

TEOS-10のGSWでは`gsw_z_from_p`の入力は海水圧[dbar]と緯度、出力は上向きを正とする高さ[m]であり、水深はその符号を反転した量になります。絶対圧か海水圧かも確認します。厳密な換算は緯度などに依存するため、「1 dbar = 1 m」を定義として使うことは勧めません。[TEOS-10 / GSW公式資料](https://www.teos-10.org/pubs/gsw/v3_04/html/gsw_z_from_p.html)

位置が未知なら、換算に使う緯度にも幅があります。最初は観測海域を代表する緯度で換算し、必要なら候補域内の緯度の違いが結果に与える影響を調べます。この換算は自分で行ってください。pangeo-fish は自動では行いません。

## 4. 鉛直座標と海面高度

静的水深を$H_0>0$、平均海面などを基準とした海面高度を$\eta$とすると、水柱の厚さは同じ基準面・符号の下で$H_0+\eta$と表せます。海面からのタグ深度と、固定基準面からの海底深度を直接比べると、潮汐や海面変動の分だけ意味がずれます。

海洋モデルは、製品ごとに深さの表し方が違います（固定の深さ、海面の上下に合わせて動く深さなど）。pangeo-fish は、モデルの種類に応じて、海面から各層までの実際の深さを求めてからタグの深度と比べます。海面が下がって水がなくなるセルは、`min_water_depth="auto"` を指定すると自動で除外されます。他のモデルを使うときは、そのモデルの深さの定義と基準の海面を、製品の仕様書で確認してください。

## 5. IBIとGLORYSを使い分ける

IBI再解析`IBI_MULTIYEAR_PHY_005_002`はIberia–Biscay–Irelandを対象とする地域プロダクトで、水平格子は1/36°（約3 km）です。GLORYS12V1の`GLOBAL_MULTIYEAR_PHY_001_030`は全球1/12°（約9 km）の再解析です。製品ID、個別dataset ID、変数、時間平均の種類、取得版は分けて記録します。[IBI公式製品ページ](https://data.marine.copernicus.eu/product/IBI_MULTIYEAR_PHY_005_002/description)／[GLORYS公式製品ページ](https://data.marine.copernicus.eu/product/GLOBAL_MULTIYEAR_PHY_001_030/description)

フランス沿岸のデモで使ったIBIは、日本周辺を含むモデルではありません。日本の事例へ移るときは、GLORYSまたは適切な地域モデルがその海域を含むか、沿岸・浅海の再現性、利用できる変数を確認します。

海洋モデルの格子を細かいHEALPixに補間しても、新しい観測情報が増えるわけではありません。水温の分布から位置をどこまで絞れるか、モデルの誤差がどのくらいかは、格子間隔とは別に評価します。

## 6. 欠測、ゼロ、海陸マスク

値0は有効な温度・海面高度であり得ます。NaNは欠測や除外を表します。候補海域の外、陸上、入力の不足、観測と矛盾するセルを、同じゼロとして一括で扱わないでください。

複数の観測重みを掛け合わせる`combine_emission_pdf`では、ある観測重みが欠測のセルは、積も欠測になって候補から消えます。また、状態確率や経路を計算する前に、正の重みが残っていない時刻があればエラーになります。

新しいデータでは、入力変換後の観測数、各観測重みが定義されるセル数、共通の日時・セルID、正の重みの総量を図に描いて確認してください。地図上の経路を見る前に行う点検になります。
