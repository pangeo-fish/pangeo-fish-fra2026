# 海底地形による制約：潜れた深さとセル内の地形

海底地形から得られる基本的な条件は、魚が記録した水深まで潜れる水柱が、その場所に存在することである。これは、魚が常に海底にいるという仮定より弱い条件である。浮魚性の魚にも、観測した潜水深度より浅い海域を候補から減らすという使い方ができる。

**実装の基準**：以下の関数、数値、挙動は、pangeo-fish `main` の `af4fe17` のソース（`pangeo_fish/bathy.py` と `notebooks/pangeo-fish-complete-demo.ipynb`）を読んで確認したものである。コードの記述は読解にもとづくもので、ノートブックを実行して確かめたものではない。説明用の理想式と実際のビン索引は分けて示す。

## 1. 水深の符号と基準面

海底水深 $H(x)>0$ を平均海面から下向き、海面高度 $\eta(x,t)$ を上向き、タグ水深 $d(t)>0$ をその時点の海面から下向きに定義すると、物理的な条件は

$$
d(t)\leq H(x)+\eta(x,t)
$$

である。海底が動かない近似の下で、海底地形と比較する深さを

$$
z_t^*(x)=\max_{i\in\text{time bin }t}\{d_i-\eta(x,t_i)\}
$$

と書ける。この式は座標の定義から導いた本教材の説明である。実際の処理（`bathy.py` の `compute_pdf_bathy_numba_like_numpy`）では、タグの `pressure` が m の水深としてそのまま使われ（単位変換のコードはない）、`XE`（参照モデルの海面高度）が差し引かれる。元データが dbar なら事前の変換が必要であり、`XE` に潮汐や基準面差のどこまでが含まれるかは、選んだ参照モデルごとに確認する。

GEBCO2024 は、標高を m で持つ15秒角格子で、海底は負の値になる。公式資料は平均海面基準を仮定しつつ、浅海の一部には異なる基準面の資料が含まれることを明記している。また、格子間隔と元の測深データの実効的な解像度は等しくない。{cite:p}`GEBCO2024`

## 2. なぜセル中心の水深だけでは足りないか

一つの HEALPix セルに大陸棚斜面が入れば、浅い部分と深い部分が共存する。セル中心の水深だけを使うと、同じセル内に実際には潜れる場所があるのに候補から除く場合がある。逆に最大水深だけを使えば、深い小部分だけがあるセルに強い重みを与える場合がある。

この違いを説明する理想化として、セル $c$ の中の水深を $H$、その分布を $p_c(H)$ とすると、深さ $z$ が可能な割合は

$$
S_c(z)=\Pr(H\ge z\mid c)=\int_z^\infty p_c(H)\,dH
$$

になる。$S_c$ は水深の生存関数である。名称に「生存」とあっても、ここでは魚の生存確率を意味しない。

例えば、同じセル内に等しい重みの8地点があり、その水深が25、35、…、95 mなら、60 mより深い4地点の割合は $1/2$ である。この値は合成した説明例であり、実際の魚がその4地点に等確率で存在するという観測結果ではない。セル内の利用可能面積、元ラスタのサンプリング重み、魚の生息場所選択が違えば、適切な重み付けも変わる。

### 海底地形の不均質性を調べる先行研究

Nielsenらは、北太平洋の平坦・斜面・不均質な海底で模擬移動を作り、深度を用いたHMMの格子幅とセル内深度分散の指定を比較した。出版社に掲載された要旨では、セル内の深度分布が正規分布から外れると性能が低下し、格子を粗くする影響や推定される拡散の値も地形・分散の指定に依存したと報告する。新しい海域で感度分析が必要という論点に直結する。{cite:p}`Nielsen2019`

この研究が現在のヒストグラム由来の深度適合度を検証したわけではない。本章への応用は、**水平セルの大きさと鉛直の深度ビン幅を別々に変え、観測重みと推定移動幅の変化を確認する**という検証方針である。これは論文の結果から導く提案であり、特定の格子・ビン幅が最適だという主張ではない。

## 3. Pangeo-Fish の実装との対応

`compute_healpix_histogram_region_bin_size` は、負の `elevation`（標高）を水深（正）に変換してビンに集め、平滑化したヒストグラムをセルごとに合計1に正規化した後、`1 - cumsum(hist)` を保存する（変数名 `bathy_pixel_hist`）。これが前節の $S_c(z)$ に対応する離散的な考え方である。ただし、厳密な閾値、ビンの端、末端のクリップ、バッファは実装に依存する。

| 項目 | 関数の既定値 | Complete デモで与えた値 | 備考 |
|---|---|---|---|
| `depth_bin_size` | 1（m） | 16 m | 深度ビンの幅（docstring は meters と記す） |
| `max_depth_m` | `None` | 1000 m | `nb_depth_bins` と `max_depth_m` のどちらかが必須で、どちらもなければ `ValueError`。`nb_depth_bins = ceil(max_depth_m / depth_bin_size)` なので、デモでは63ビン |
| `depth_offset` | 0 | 指定なし | 水深を `(-elevation - depth_offset) / depth_bin_size` として計算する際に引く値 |
| `chunk_size` | 500 | 指定なし | 一度に読む緯度の行数（ヒストグラムの集計を行う単位） |
| `ellipsoid` | `"sphere"` | 研究設定の `ellipsoid`（配布デモの値は `"sphere"`。`"WGS84"` はコメントで選択肢として示される） | セルIDの計算に使われる（下記） |
| 入力の海底地形 | 関数に渡すデータセット（`elevation` が必須、`stdev` は任意） | `gebco_2024_new.zarr`。領域（`bbox`）の外側に0.1度の余白を付けて切り出す | |
| `batch_compute_pdf_bathy` の `batch_size` | 50,000（セル） | 10,000 | 一度に水深尤度を計算するセル数 |

`ellipsoid` は、地理座標からセルIDを求める段階（`lonlat_to_healpix`）に渡される。一方、出力に付くセルの `latitude`／`longitude` 座標は `healpy.pix2ang`（球面）で作られている（`ellipsoid` 付きで計算した `lon_2`／`lat_2` は作られるが使われない）。また出力の `cell_ids` の属性は `grid_name`、`nside`、`nest` で、`ellipsoid` は含まれない。`"WGS84"` を選んだ実行では、この `latitude`／`longitude` を地図上の位置として使わず、`cell_ids` で他の観測項と照合する。

### 実装固有の値を科学的な誤差モデルと混同しない

水深項は、概念上、次の索引でヒストグラムを引く。ヒストグラムを作る側（`bathy.py` 112–114行）と、タグの水深で引く側（同 204、214行）で、それぞれ `10` が現れる。

- **ヒストグラム側**：`depth_idx = int(clip((-elevation - depth_offset)/Δz, -10, nb_depth_bins - 0.01)) + 10`（$\Delta z$ は `depth_bin_size`）。ここの `+10` は**ビン数**での平行移動である。配列は `nb_depth_bins + 10` 列で作られ、先頭の10列がバッファ（水深が負の値、つまり陸側を受ける）に当たる。正規化後、出力に残すのは先頭の `nb_depth_bins` 列だけで、末尾の10列は捨てられる。
- **引く側**：$\mathrm{bin}=\operatorname{clip}\left[\operatorname{int}\left\{\dfrac{\max_i(d_i-XE)+10}{\Delta z}\right\}\right]$。ここの `+10` は**m**の値として足される。

この `+10` の意味づけには注意が必要である。`depth_bin_size = 1`（既定値）なら、引く側の10 mはちょうど10ビンに当たり、二つの `10` は一致する。しかし Complete デモのように `depth_bin_size = 16` とすると、引く側の10 mは0.625ビンにしかならず、ヒストグラム側の10ビン（160 m）と一致しない。ソースを読んだ算術では、この場合に参照される列は、観測水深より約150 m浅い水深に対応する位置になる。つまり水深項が実効的に弱くなる可能性がある。これはコードの読解からの指摘であり、本書では実行して確かめていない。ビン幅を1 m以外にして使う場合は、既知の水深のセルで引いた値を確かめるまで、この項を校正済みとして扱わない。

**この `+10` に対して、測深誤差補正、海図基準面補正、一定の安全余裕といった意味を根拠なく付けない。** ソースのコメントには「historic behaviour: we keep +10 buffer bins as in original code」とあり、バッファの列数に由来する値である。

平滑化は、5ビン（$-2,\dots,+2$）の重み $\exp\{-dj^2/(2\,\mathrm{stdev}^2)\}$ を合計1にそろえて配る処理で、入力 `stdev` の値は**ビン単位**の広がりとしてそのまま使われる（`depth_bin_size` で割られない）。`stdev` が m で与えられるなら、ビン幅を変えると物理的な広がりも変わる。`stdev` が入力データにない場合は全セル1.0が使われ、欠測は1.0に置き換えられ、いずれの場合も最小値は0.5に切り上げられる。これらを一般に推奨される測深誤差として説明しない。なお、デモで使うラスタに `stdev` が含まれるかどうかは、ソースからは確認できていない。

現段階では、この項を「水深との適合度」または「セル内の水深分布に基づく位置重み」と説明するのが明確である。特定海域の測深誤差を校正し、魚のセル内分布を含めて妥当性を確かめる前に、校正済みの確率と呼ばない。

実装出典：[水深値の索引、床値、欠測処理](https://github.com/pangeo-fish/pangeo-fish/blob/af4fe17/pangeo_fish/bathy.py#L165-L222)。

## 4. 欠測、床値、正規化

コードでは、最初の時刻で `XE` が欠測でないセル（海のセル）について、ヒストグラムの値が0以下または欠測のとき `1e-14` の床値が与えられる（`bathy.py` 174–183行）。したがって、これは常に完全な0/1の排除ではない。一方、`XE` が欠測のセル（陸）には `NaN` が返り、ヒストグラム自体も `NaN` になる。タグの水深がその時刻ビンで全欠測のときも `NaN` が返る（188–190、209–211行）。床値と欠測は別の意味を持つ。

引く側の `bin_idx` は0以上 `B-1` 以下（$B$ は出力の列数）にクリップされる（213–218行）。すなわち、設定した最大水深（デモでは1000 m）より深い観測は最後の列で扱われる。

空間的な正規化は、ある時刻のセル間比較をしやすくする。デモでは、`batch_compute_pdf_bathy` の出力を、全セルの和（`NaN` を除く）で割って正規化している。ただし、総和を1にしたというだけで海底地形の不確実性や生息場選択をすべて含む事後確率になるわけではない。最終的な位置分布は、ほかの観測と HMM の移動・端点条件を加えて決まる。

`NaN` を含む観測項が積に入ると、そのセルを失う場合がある。各時刻で有効セル数と正の重みの総量を確認し、海底地形を追加した直後に候補が消えていないかを見る。これは推定結果の善し悪しを判断する前の、入力の整合性の確認である。

## 5. 潮汐項との組み合わせ

水深の最大値から海底地形項を作り、同じ時系列の周期変動から潮汐項を作る。情報の特徴は異なるが、元の観測は共有されている。legacy 潮汐のように、モデルの水柱厚 `WCT` を使って絶対水深を既に比較に含める場合は、海底地形の条件が重複する可能性を特に説明する。

HEALPix 方式の潮汐（`water_column=None`）は、セルごと・日ごとに平均水深を推定して取り除くため、絶対水深と波形の役割を分けやすい。Complete デモは、絶対水深の情報を別の海底地形項に任せている。ただし、そのことだけで両項の条件付き独立性が証明されたわけではない。比較実験では、海底地形の追加で分布が狭くなるだけでなく、独立の既知位置をどれだけ含むかを調べる。

## 6. 面談で使う確認表

| 相談事項 | 見たい図・資料 | 判断へのつながり |
|---|---|---|
| 対象海域の海底地形は十分か | GEBCO の TID と、利用可能なら局所測深との比較 | 直接測深・補間などのデータ来歴を把握する |
| タグは何を記録したか | pressure/depth の単位、校正資料、変換式 | m と dbar の混同を避ける |
| 深度の基準面は揃っているか | 海面高度、平均海面、海図基準面の関係図 | 系統的な水深差を見分ける |
| 格子とビン幅の影響は何か | level・水深ビン幅を変えた適合度地図 | 空間離散化と鉛直離散化の影響を分ける |
| 小さな深場が支配していないか | セル内ヒストグラムと生存関数 | 単一の代表水深では見えない構造を確認する |

GEBCO の TID は元データの種類を示す資料であり、各セルの数値的な標準偏差をそのまま提供する変数と同一視しない。デモで使うラスタに `stdev` がある場合は、誰がどの計算で作った変数かまで記録する。{cite:p}`GEBCO2024`
