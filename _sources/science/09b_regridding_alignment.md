# 再格子化と格子・時刻の整合

## 1. 格子をそろえる作業も観測モデルの一部

水温、潮汐、海底地形、音響の記録は、もともとの空間解像度、時間間隔、座標の持ち方が異なります。pangeo-fish でそれらを掛け合わせるには、「同じ時刻の同じ候補位置を評価している」という条件を満たす必要があります。

この条件は、配列の長さが一致するだけでは満たされません。例えば水温の尤度（likelihood）がセルID `[10, 20, 30]`、音響の尤度（likelihood）が `[30, 10, 20]` の順なら、配列の位置で掛け合わせると、違う場所の観測を組み合わせてしまいます。IDが同じでも、格子の level や地球の形が違えば、やはり意味が異なります。

## 2. 再格子化で保存したい量を決める

異なる格子を同じ HEALPix に移すときは、変数の意味に応じて操作を選ぶ必要があります。次の表は手法を選ぶときの考え方で、すべてを pangeo-fish が実装しているという一覧ではありません。

| 量 | 考える操作 | 確認したいこと |
|---|---|---|
| 水温のような連続的な場 | 近傍値、面積で重み付けした平均など | 元データが点の値かセルの平均か、陸をまたぐ補間になっていないか |
| セルの確率質量 | 面積の重なりに応じた配分・集約 | 合計が保たれているか、観測のない領域へ質量を移していないか |
| 確率密度 | 密度として求め直した後、セル面積に合わせる | 質量と密度を同じ配列として扱っていないか |
| 水深の分布 | 元の深度情報をセル内の分布として集約 | 平均水深だけでは消えてしまう浅瀬・深場の情報 |
| 潮汐の調和定数 | 複素数表現の実部・虚部など、周期性を保つ補間 | 位相0度と360度の境界、単位と位相の基準 |

特に、非線形の変換は順序に注意します。温度差 $r$ から $L(r)=\exp[-r^2/(2s^2)]$ を作る場合、一般に

$$
L\!\left(\sum_i w_i r_i\right)
\ne \sum_i w_iL(r_i),\qquad \sum_i w_i=1.
$$

となります。例えば $r_1=1$、$r_2=-1$、等しい重みなら、平均した差は0ですが、各場所の差は0ではありません。先に差を平均する場合と、各場所の尤度（likelihood）を平均する場合では、科学的な意味が異なります。

pangeo-fish の温度の処理は次の順序です。

1. 各時間ビンの中で、タグの水温とモデルの水温の差（タグ − モデル）を、モデルの最も近い深さについて求め、ビン内で平均します。
2. この符号付きの平均差を HEALPix の格子に移します（補間と海陸マスクの扱いはこの段階です）。平均差の値は 0 に切り上げません。
3. 最後に、平均0・標準偏差 `differences_std` の正規分布の密度として、観測の重み（尤度（likelihood））を作ります。

つまり、再格子化されるのは尤度（likelihood）ではなく**平均差**で、尤度（likelihood）への変換はその後です。正規分布は0を中心に対称なので、差の向き（タグ − モデル）は重みに影響しません。一方、負になってはいけない量（潮汐の確率密度）を補間すると、小さな負の値が出ることがあります。デモのノートブックでは、これを `clip(min=0)` で0に切り上げています。

## 3. 共通のセルと共通の時刻を先に確定する

観測の情報を統合する前に、次の三つを順に確認します。

1. **格子の一致**：level、番号の付け方、地球の形、セルの地理的な位置。
2. **ラベルの一致**：実際に存在するセルIDと時刻。
3. **値の意味の一致**：欠測、0、情報なし、海陸マスク、単位。

三つ目の「情報なし」「0」「NaN」は、次のように意味が違います。「情報なし」の観測は 1 とします（掛け算しても結果が変わりません）。0 は、その場所を候補から除きます。NaN は欠測を表し、掛け算や正規化でどう扱われるかは実装によります。この三つを同じものとして扱ってはいけません。

Complete デモは、観測の項を次のように結合します。

| 観測の項 | 結合のしかた |
|---|---|
| 音響・海底地形 | セルIDを照合せず、配列の並び順で結合します。そのため、セルの数と並びが一致していることが前提です。デモでは、結合の前に海底地形を総合 PDF のセルID・時刻に合わせています。 |
| 潮汐 | 日ごとの潮汐 PDF を、セルIDと日付で選んで結合します。格子の定義が両者で食い違うとエラーにします。潮汐のデータがないセルや日には、一定の中立な値が入り、件数が警告で報告されます。 |
| 全項の統合 | 各項を掛け合わせて空間で正規化します。NaN が一つでもあるセルは NaN になります。全セルが欠測の時刻があると警告が出ます。 |

結合は、「データの形がそろった」ことの確認だけでは足りません。「それぞれの項が同じ場所・同じ時刻を指している」ことの確認が必要です。特に音響と海底地形は並び順で結合されるので、自分のデータを使うときは、結合の前に `cell_ids` を直接比べてください。

潮汐はセルと日を落とさず中立な値で埋めますが、共通する部分だけを残す結合では、解析する期間や候補の海域が狭まる可能性があります。結合の前後で時刻の数、セルの数、欠測の位置を比べ、除かれた場所や日付が研究上の意味を持たないか確認します。潮汐で中立な値が入った日についても同様です。

## 4. メタデータは座標の意味を保存する

格子のメタデータには、セルIDから地理的な位置を再現するための情報が必要です。DGGS の概念とAPIの対象は、それぞれ OGC の文書で整理されています。PROJ の HEALPix も、球の形と楕円体の形を区別して扱います。{cite:p}`ogc2021dggs,ogc2025apidggs,proj_healpix`

教材と各実例には、少なくとも次を記録します。

| 記録項目 | 研究上の意味 |
|---|---|
| pangeo-fish と FRA のコミット | 説明・ノートブック・実装の対応 |
| コンテナタグ、可能ならダイジェスト | 実行した依存関係を再現する |
| 元データのID、版、取得時点、対象期間 | 更新や欠測を含むデータの来歴 |
| level／nside、NESTED／RING | セルの階層と整数IDの解釈 |
| 地球の形（楕円体の名前） | セルIDと地理的な位置、面積の関係 |
| `cells` と時間座標 | 解析する海域のセルと実際の時刻が対応しているか |
| 変数の単位、深さの符号、鉛直の基準面 | 温度・深度・潮汐を比べる前提 |
| マスクの作成方法、海の割合の扱い | 魚がいられる領域の定義 |
| 再格子化の方法と、尤度（likelihood）への変換の順序 | 何を平均・補間したか |

**メタデータを書き換えることと、データを変換することは別の操作です。** 値やセルIDを作ったときの地球の形と、メタデータに書いた地球の形が食い違っていると、観測を別の場所に割り当ててしまいます。文字列を書き換えるだけでは、値は変換されません。

pangeo-fish は、格子の定義（`grid_name`、level、番号の付け方、`ellipsoid`）をデータと一緒に保存し、読み戻しても保たれるようにしています。再格子化の設定（`resolution_2D`、`refinement_level`、`ellipsoid`）は、デモが書く `resampling_info.json` に残ります。ワークショップの格子はすべて WGS84 です。楕円体の扱いは[楕円体HEALPix](09_ellipsoidal_healpix.md)の第7節にまとめています。

計算量・チャンクと移動の計算は[データ処理と計算](10_computing.md)へ、格子の幾何学は[楕円体HEALPix](09_ellipsoidal_healpix.md)へ進みます。
